# Research and result provenance

The corrected entry point is `scripts/fyp.py`. This directory preserves useful pre-correction research without presenting inherited results as current evidence.

## Historical results (preserved at original paths)

`historical_artifact_inventory.json` identifies 79 existing result files by path, size and SHA256. It includes `results/tables`, `results/figures`, `data/results`, `data/figures` and notebook CSV/PNG exports. These files were not regenerated by the corrective pass. Their metrics reflect the old windows and, where applicable, old scaling, tuning or normalization. None is designated a corrected final result.

`legacy_code_manifest.json` identifies the byte-preserved pre-edit ML/KD, plotting and experiment implementations in `legacy_code/`. They have `.py.txt` suffixes to make their archival status explicit. Old experiment and plotting entry points now stop with a migration message; the numbered current pipeline scripts delegate to shared code. This prevents obsolete routines from silently overwriting inherited results.

`notebook_snapshots/` preserves both notebooks as supplied before this implementation pass, including historical outputs and errors. `notebook_snapshot_manifest.json` records their hashes. Current notebooks have portable path setup, unique exploratory output directories, disambiguated CR output filenames and explicit exclusion of the undefined SR diagnostic/superseded plotting cell. Their scientific methods and long simulation results have not been validated by a full notebook rerun.

## Corrected, validation and final runs

New data is under `data/processed/corrected_v2`; old feature tables remain intact. Each corrected experiment has a fresh `results/corrected/<run-id>` directory. A manifest records its dataset checksum, configuration, source hashes, seed(s), patient folds, status and whether it is validation-only. Metrics, predictions and bundles belong to that run only. Reports consume that explicit run and refuse existing figure directories.

`results/corrected/implementation-validation` holds compact correctness receipts and counts. `validation-kd-chb08-seed42-v2` and `validation-ml-chb08-seed42` are integration checks, not final five-patient results. No corrected final experiment is designated yet. Full LOPO and paired multi-seed comparisons remain pending. A completed full run must still be reviewed before its results are used in the dissertation.

New notebook runs use unique subdirectories of `results/exploratory`; they are separate from canonical evaluation. SR, coherence resonance, compression/reconstruction, PSD and noise require their own scientific review. In particular, do not conflate the original compression/reconstruction abbreviation CR with later coherence-resonance code.

The initial `validation-kd-chb08-seed42` run and its `demo-kd-*` outputs are superseded by the `-v2` validation artifacts. The initial bundle reported the default epoch count in one metadata field, although its run manifest correctly recorded two epochs. The v2 run fixes that bundle field and repeats the same seeded experiment.
